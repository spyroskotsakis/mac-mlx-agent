Now that we have an agent talking to MLX, let's look at how MLX gets the most out of
your hardware and addresses the key challenges of running agents locally.
The first challenge is prompt processing.
In an agentic workflow, every time the model receives too much output, it has to process
all that new context before it can reason about the next step.
This happens over and over throughout the agentic loop and it adds up fast.
Agentic sessions usually comprise hundreds of thousands of tokens and most of those
are not generated.
The M5 sheet introduces dedicated neural accelerators and MLX can target them for exactly
this kind of work.
Specifically, neural accelerators make matrix multiplication four times faster on M5 compared
to M4.
And with a specialized multiplication and attention kernels in MLX, this translates
almost exactly to prompt processing speedup.
Reducing prompt processing time means your agents can read your code base or process
too little results almost four times faster.
And the best part, taking advantage of neural accelerators requires no spatial arguments
or code changes on your part.
MLX selects the best kernel for the available hardware and it just works.
Let's now talk about the second challenge, concurrency.
In practice, agents readily work alone.
A common pattern is for an agent to spawn several sub-agents, each tackling a different
part of the problem in parallel.
One might be reading documentation, another searching code, and a third writing tests.
All at the same time.
That means multiple requests hitting your local model simultaneously.
MLXLM server handles this with continuous batching.
Instead of processing requests one at a time, it dynamically groups incoming requests into
batches and processes them together on the GPU.
New requests can join a batch in progress without waiting for the current one to finish.
The result is that your sub-agents don't stall waiting in a queue.
They all get served concurrently, which keeps the entire agent workflow moving.
Finally, the third challenge is model size.
Sometimes a single machine, even one with 512 gigabytes of RAM, just isn't enough because
the model is too large to fit in memory.
The most recent DeepSync model, for instance, has a whopping 1.6 trillion parameters and
requires more than 800 gigabytes of memory just for the weights.
MLX's distributed support lets you spread the model across multiple Macs connected over
Thunderbolt or Ethernet.
For agents, this is powerful in two ways.
First, it lets you run much larger, more capable models that wouldn't fit on a single machine.
Second, it parallelizes prompt processing across devices, which directly speeds up the
agenda loop since the model can process tool results faster.
Setting up distributed inference with MLXLM server is fairly straightforward.
We launch the server using MLX launch and a host file that contains information about
the nodes and the type of connection.
The model is automatically started across all available devices, and everything else
just works.
Starting with Mac OS 26.2, we have support for Thunderbolt RDMA, which provides low-latency
high-bandwidth communication over Thunderbolt.
As a result, distributed inference with MLX has seen significant speed-ups up to three
times with four nodes.
